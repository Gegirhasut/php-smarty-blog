# Блог на PHP + Smarty + MySQL

Инструкции для Claude Code в этом репозитории. Блог с категориями и статьями на чистом PHP 8.1+, без фреймворков.
План работы - `docs/plan.md`, макеты - `docs/design/`. Документация - `README.md` и `docs/` (архитектура, база, ИИ, скриншоты):
при изменении поведения, команд или структуры её нужно обновить.

## Запуск
- `docker compose up -d --build` - сайт на http://localhost:8080 (порт - `APP_PORT`).
- Код монтируется в контейнер, правки видны сразу; скомпилированные шаблоны Smarty лежат в томе `var`.
- Стили: сервис `sass` (dart-sass из стадии `sass` в `Dockerfile`) собирает `assets/scss/app.scss` в `public/assets/css/app.css`
  и пересобирает при каждом изменении; nginx стартует после первой сборки. Собранный CSS в git не попадает.
  Ошибка в SCSS - в `docker compose logs sass`.
- `docker compose exec php php bin/seed.php --fresh` - пересоздать таблицы по `database/schema.sql` и заполнить базу из `database/seeds/`.
  Схема применяется целиком, изменения - через `--fresh`, данные учебные (миграций нет).
  `--posts=N` - ещё N сгенерированных статей (`src/Seed/PostGenerator.php`) для проверки на объёме.
- Тестовая база `blog_test` создаётся скриптом из `docker/mysql/init` при первом создании тома MySQL;
  если том старше этого скрипта - `docker compose down -v`.
  Тесты берут имя базы из `DB_TEST_NAME` (по умолчанию `blog_test`); compose её не задаёт, init-скрипт создаёт только `blog_test`.

## Тесты и анализ
- `docker compose exec php composer test` - PHPUnit; один набор: `composer test -- --testsuite unit`.
- `docker compose exec php composer analyse` - PHPStan, уровень max, без baseline.
- `tests/Unit` - классы и шаблоны по отдельности, `tests/Functional` - приложение целиком через `App::handle()` без HTTP,
  `tests/Integration` - на настоящем MySQL в базе `blog_test` (`composer test -- --testsuite integration`).
- Тестам с базой - `tests/DatabaseTestCase.php`: схема пересоздаётся раз за запуск, перед каждым тестом таблицы очищаются,
  фикстуры - `insertCategory()` и `insertPost()` (первая категория в списке - основная). `$rollBack = true` ведёт тест
  в транзакции с откатом - так работают тесты репозиториев и страниц. Функциональные без базы (`AppTest`) проверяют,
  что соединение не открывается. Части страниц тесты ищут по смыслу разметки (`aria-label`, заголовки), а не по CSS-классам.
- CI (`.github/workflows/ci.yml`): `composer validate --strict`, PHPStan и PHPUnit на PHP 8.1 и 8.5, отдельной задачей - сборка SCSS
  стадией `sass` из `Dockerfile`; на push в `main` и в pull request.

## Маршруты
- `/` - главная: категории со статьями, в каждой три последние статьи и ссылка «Все статьи».
- `/category/{slug}?sort=date|views&page=N` - категория. Некорректные `sort`/`page` и страница после последней - 404,
  `?sort=date` и `?page=1` - 301 на адрес без них.
- `/post/{slug}` - статья: просмотр засчитывается на GET (не на HEAD), справа три похожие статьи (из 50 последних
  каждой её категории, больше общих категорий - выше; не хватает - добираются самыми свежими) и список категорий.
- `/sitemap.xml` - индекс sitemap: `/sitemap-categories.xml` (главная и категории) и `/sitemap-posts-N.xml` (статьи
  с id от 1000·(N-1)+1 до 1000·N), `/feed.xml` (RSS 2.0, 20 последних), `/llms.txt` (по 20 свежих статей каждой
  категории) - из базы; `/robots.txt` со ссылкой на индекс sitemap - без базы.
- slug - только латиница в нижнем регистре, цифры и дефисы, не одни цифры (`Slug`); другой адрес - 404 ещё до запроса к базе.
- Адрес маршрута со слэшем на конце (`/post/slug/`) - 301 на адрес без слэша с тем же query.
- Остальное - 404, методы кроме GET и HEAD - 405; на них соединение с БД не открывается.

## Структура
- `public/index.php` - единственная точка входа, nginx отдаёт в неё всё, кроме статики.
- `src/Core` - ядро: `App` (маршруты и обработка запроса), `Router`, `Request`, `Response`, `View` (Smarty), `Pagination`,
  `Config` (название, описание, адрес и картинка сайта), `Env`.
- `src/Database` - подключение PDO, `Row` (строка результата с проверкой типов) и применение схемы.
- `src/Seed` - сидер: читает и проверяет `database/seeds`, копирует обложки, затем пересоздаёт таблицы (`--fresh`)
  и пишет в базу через репозитории; база меняется только после проверки данных.
- `src/Repository` - все SQL-запросы; возвращают сущности из `src/Blog`, а не массивы, и сами собирают их из строк `Row`:
  предметная область о базе не знает.
- `database` - `schema.sql` и данные сидера в `seeds/` (категории, статьи, обложки); `bin/seed.php` - запуск сидера.
- `src/Controller` - тонкие контроллеры: разбирают запрос, зовут репозитории, отдают данные в шаблон.
- `src/Blog` - предметная область без SQL: сущности `Category`, `PostCard` (статья в списках) и `Post` (статья целиком),
  `Slug`, `Sort` и `ListingQuery` (разбор `sort`/`page`), `ArticleText` (текст статьи на блоки), `Urls` (схема адресов).
- `src/Seo` - `Meta` и `PageMeta` (мета-теги, хлебные крошки и JSON-LD страниц), `Sitemap`, `RssFeed`, `LlmsTxt`.
- `templates` - Smarty: `layout.tpl` и шаблоны страниц, общие куски в `partials/` (карточка, обложка, пагинация, крошки,
  иконки), ошибки в `errors/`.
- `assets/scss` - стили: `abstracts` (брейкпоинты, миксины), `base` (шрифт, CSS-переменные темы, сброс), `layout`,
  `components` (BEM-блоки), `pages`. `public/assets` - шрифты, картинки оформления и собранный CSS; в корне `public` -
  favicon, иконки для телефона, `site.webmanifest` и `og.jpg`.
- `Dockerfile` (стадия `sass` - сборщик стилей, последняя - PHP для разработки) и `docker/nginx` - окружение для разработки.

## Правила кода
- `declare(strict_types=1)`, типы везде, `final` и `readonly` где уместно.
- Без фреймворков. В рантайме из Composer только Smarty; PHPUnit и PHPStan - только dev.
- SQL только в репозиториях, только prepared statements. Значения для `ORDER BY` - только из белого списка.
  Строки результата читаются через `Row`, без `@var` на `fetchAll()`.
- Адреса страниц собирает только `Urls`, в шаблонах он доступен как `$urls`.
- Время в базе - UTC (`published_at`); `public/index.php` и PHPUnit работают в UTC, `Row::date()` читает дату в UTC.
- Контроллеры тонкие, шаблоны без логики. Зависимости - через конструктор, собираются в `App`; без статического и глобального
  состояния, кроме настройки PHP в `public/index.php` (обработчик ошибок, вывод ошибок, UTC) и seed `mt_rand()` в `PostGenerator`.
- Соединение с БД открывается лениво: `App` получает фабрику PDO и вызывает её при первом обращении, в тестах фабрика подменяется.
- Вывод в шаблонах экранируется по умолчанию; `nofilter` - только для заранее безопасных данных (JSON-LD).
  Текст статьи не HTML: `ArticleText` делит его на блоки, теги строит шаблон.
- Smarty - только для HTML. XML (sitemap, RSS) собирает `XMLWriter`, текст (robots, llms) - PHP: HTML-экранирование испортило бы их.
- Файлы оформления из `public/assets` подключаются через модификатор `asset` (`{'/assets/css/app.css'|asset}`): он дописывает
  `?v=` со временем изменения, а nginx отдаёт `/assets/` с кэшем на год. Шрифты из CSS - без версии, их файлы не меняются.
- Вёрстка: mobile-first, классы по BEM, без CSS-фреймворков; текущий пункт меню, сортировки и страницы стилизуется по `aria-current`.
  Иконки - только Lucide (ISC) через `partials/icon.tpl`, иконка и заглушка обложки категории - по slug в `partials/category-art.tpl`.
  Картинки и графику не рисовать кодом - их заказывает владелец.
- Комментарии только там, где неочевидно «почему». Комментарии и тексты для пользователя - на русском.
- Простота важнее «энтерпрайзности»: не добавлять слои и абстракции без реальной нужды.

## Порядок работы
- Работаем по этапам из `docs/plan.md`; каждый этап - несколько небольших коммитов.
- Сообщения коммитов короткие, по-русски: `область: что сделано` (`каркас: роутер и шаблон Smarty`).
- Новый код приходит вместе с тестами; перед коммитом зелёные тесты и PHPStan.
- После этапа - независимое ревью, исправления до чистого результата, затем push.
- Не трогать чужие контейнеры на машине; работать только со стеком из `compose.yaml`.
