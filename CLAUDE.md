# Блог на PHP + Smarty + MySQL

Инструкции для Claude Code в этом репозитории. Блог с категориями и статьями на чистом PHP 8.1+, без фреймворков.
План работы - `docs/plan.md`, макеты - `docs/design/`.

## Запуск
- `docker compose up -d --build` - сайт на http://localhost:8080 (порт - `APP_PORT`).
- Код монтируется в контейнер, правки видны сразу; скомпилированные шаблоны Smarty лежат в томе `var`.
- `docker compose exec php php bin/seed.php --fresh` - пересоздать таблицы по `database/schema.sql` и заполнить базу из `database/seeds/`.
  Схема применяется целиком, изменения - через `--fresh`, данные учебные (миграций нет).
- Тестовая база `blog_test` создаётся скриптом из `docker/mysql/init` при первом создании тома MySQL;
  если том старше этого скрипта - `docker compose down -v`.
  Тесты берут имя базы из `DB_TEST_NAME` (по умолчанию `blog_test`); compose её не задаёт, init-скрипт создаёт только `blog_test`.

## Тесты и анализ
- `docker compose exec php composer test` - PHPUnit; один набор: `composer test -- --testsuite unit`.
- `docker compose exec php composer analyse` - PHPStan, уровень max, без baseline.
- `tests/Unit` - классы и шаблоны по отдельности, `tests/Functional` - приложение целиком через `App::handle()` без HTTP,
  `tests/Integration` - на настоящем MySQL в базе `blog_test` (`composer test -- --testsuite integration`).
- Тестам с базой - `tests/DatabaseTestCase.php`: схема пересоздаётся раз на класс, перед каждым тестом таблицы очищаются,
  фикстуры - `insertCategory()` и `insertPost()`. Функциональные без базы (`AppTest`) проверяют, что соединение не открывается;
  страницы (`PagesTest`) работают на тестовой базе, каждый тест в транзакции с откатом.
- CI (`.github/workflows/ci.yml`): `composer validate --strict`, PHPStan и PHPUnit на PHP 8.1 и 8.5 - на push в `main` и в pull request.

## Маршруты
- `/` - главная: категории со статьями, в каждой три последние статьи и ссылка «Все статьи».
- `/category/{slug}?sort=date|views&page=N` - категория. Некорректные `sort`/`page` и страница после последней - 404,
  `?sort=date` и `?page=1` - 301 на адрес без них.
- `/post/{slug}` - статья: просмотр засчитывается на GET (не на HEAD), справа похожие статьи и список категорий.
- `/sitemap.xml`, `/feed.xml` (RSS 2.0, 20 последних), `/llms.txt` - из базы; `/robots.txt` - без базы.
- Остальное - 404, методы кроме GET и HEAD - 405; на них соединение с БД не открывается.

## Структура
- `public/index.php` - единственная точка входа, nginx отдаёт в неё всё, кроме статики.
- `src/Core` - ядро: `App` (маршруты и обработка запроса), `Router`, `Request`, `Response`, `View` (Smarty), `Meta` (SEO),
  `Pagination`, `Config` (название, описание и адрес сайта), `Env`.
- `src/Database` - подключение PDO, применение схемы и сидер; `src/Repository` - все SQL-запросы к таблицам.
- `database` - `schema.sql` и данные сидера в `seeds/` (категории, статьи, обложки); `bin/seed.php` - схема и сидинг.
- `src/Controller` - тонкие контроллеры: разбирают запрос, зовут репозитории, отдают данные в шаблон.
- `src/Blog` - логика блога без SQL и HTTP: `ListingQuery` и `Sort` (разбор `sort`/`page`), `ArticleText` (текст статьи на блоки),
  `PageMeta` (мета-теги, хлебные крошки и JSON-LD страниц), `Sitemap`, `RssFeed`, `LlmsTxt`.
- `templates` - Smarty: `layout.tpl` и шаблоны страниц, общие куски в `partials/` (карточка, обложка, пагинация, крошки), ошибки в `errors/`.
- `Dockerfile` и `docker/nginx` - окружение для разработки; образ для демо появится на этапе 6.

## Правила кода
- `declare(strict_types=1)`, типы везде, `final` и `readonly` где уместно.
- Без фреймворков. В рантайме из Composer только Smarty; PHPUnit и PHPStan - только dev.
- SQL только в репозиториях, только prepared statements. Значения для `ORDER BY` - только из белого списка.
- Контроллеры тонкие, шаблоны без логики. Зависимости - через конструктор, собираются в `App`; без статического и глобального состояния.
- Соединение с БД открывается лениво: `App` получает фабрику PDO и вызывает её при первом обращении, в тестах фабрика подменяется.
- Вывод в шаблонах экранируется по умолчанию; `nofilter` - только для заранее безопасных данных (JSON-LD).
  Текст статьи не HTML: `ArticleText` делит его на блоки, теги строит шаблон.
- Smarty - только для HTML. XML (sitemap, RSS) собирает `XMLWriter`, текст (robots, llms) - PHP: HTML-экранирование испортило бы их.
- Комментарии только там, где неочевидно «почему». Комментарии и тексты для пользователя - на русском.
- Простота важнее «энтерпрайзности»: не добавлять слои и абстракции без реальной нужды.

## Порядок работы
- Работаем по этапам из `docs/plan.md`; каждый этап - несколько небольших коммитов.
- Сообщения коммитов короткие, по-русски: `область: что сделано` (`каркас: роутер и шаблон Smarty`).
- Новый код приходит вместе с тестами; перед коммитом зелёные тесты и PHPStan.
- После этапа - независимое ревью, исправления до чистого результата, затем push.
- Не трогать чужие контейнеры на машине; работать только со стеком из `compose.yaml`.
