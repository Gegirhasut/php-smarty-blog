# Архитектура

Блог на PHP 8.1+ без фреймворков: свой роутер и сборка зависимостей вручную, Smarty только для HTML, весь SQL в репозиториях.
Из Composer в рантайме - только Smarty.

## Путь запроса

1. nginx отдаёт статику сам, остальное передаёт в `public/index.php`. Это единственный PHP-файл, доступный снаружи,
   а адрес `/index.php` отвечает 404, чтобы у страниц не было дублей.
2. `index.php` превращает предупреждения PHP в исключения, ставит UTC, читает `Config` из окружения и создаёт `App`
   с фабрикой соединения с базой.
3. `App::handle()`: методы кроме GET и HEAD - 405. `Router` ищет маршрут по сегментам пути (`/category/{slug}`),
   совпавший маршрут создаёт контроллер и его репозитории.
4. Контроллер разбирает запрос (`Slug`, `ListingQuery`), получает данные из репозиториев и отдаёт их в шаблон вместе
   с мета-тегами из `PageMeta`.
5. Репозиторий выполняет подготовленный запрос и собирает сущности (`Category`, `PostCard`, `Post`) из строк `Row`,
   который проверяет тип каждой колонки.
6. `View` рендерит шаблон Smarty, `Response` отправляет код, заголовки и тело.

`NotFoundException` из любого места - страница 404, любое другое исключение - запись в лог и страница 500
(в `APP_ENV=dev` с текстом ошибки).

## Слои

- `Core` - `App` (маршруты и сборка зависимостей), `Router`, `Request`, `Response`, `View`, `Pagination`, `Config`, `Env`.
- `Controller` - тонкие: ни SQL, ни HTML, только «разобрать запрос - взять данные - отдать в шаблон».
- `Repository` - весь SQL: только prepared statements, порядок сортировки выбирается `match` по enum `Sort`.
  Возвращают сущности, а не массивы.
- `Blog` - предметная область без SQL: сущности, `Slug`, `Sort`, `ListingQuery`, `ArticleText`, `Urls`.
- `Seo` - `Meta` и `PageMeta` (мета-теги, крошки, JSON-LD), `Sitemap`, `RssFeed`, `LlmsTxt`.
- `Database` - `Connection` (PDO с исключениями и настоящими prepared statements), `Row`, `Schema`.
- `Seed` - сидер: читает `database/seeds`, копирует обложки, пишет в базу через репозитории.

Зависимости идут в одну сторону: контроллеры → репозитории → сущности. Предметная область не знает о базе,
статического и глобального состояния нет.

## Ключевые решения

- **Без фреймворков.** Маршрутов семь, нужны только постоянные сегменты и `{slug}` - на это хватает роутера примерно в 60 строк.
  DI-контейнер не нужен: зависимости собираются в одном месте, в `App`.
- **Ленивое подключение к базе.** `App` получает замыкание, которое открывает PDO при первом обращении к репозиторию.
  404, 405 и `robots.txt` обходятся без базы, а тесты подменяют фабрику и проверяют, что соединение не открывалось.
- **Адреса в одном месте.** Ссылки собирает только `Urls`, шаблоны получают его как `$urls`. Для ссылок на сайте - пути,
  для canonical, sitemap, RSS и llms.txt - полные адреса из `APP_URL`.
- **Строгие адреса категорий.** `ListingQuery` разбирает `sort` и `page`, решение принимает контроллер:
  мусорные значения и страница после последней - 404 (первая страница вместо них была бы дублем с кодом 200),
  `?sort=date` и `?page=1` - 301 на адрес без них. Список по просмотрам закрыт `noindex, follow`.
- **Slug.** Только латиница в нижнем регистре, цифры и дефисы; колонка в `ascii_bin`. Одни цифры нельзя:
  такой ключ в картах slug => значение PHP превращает в число, а о статье он ничего не говорит. Адрес не по формату - 404 ещё
  до запроса: MySQL не сравнивает ascii-колонку с кириллицей и отвечает ошибкой, а не «не найдено».
- **Безопасный вывод.** Smarty экранирует всё по умолчанию. Текст статьи хранится без HTML - абзацы, подзаголовки `## `
  и пункты `- `; `ArticleText` делит его на блоки, теги строит шаблон. `nofilter` есть только у JSON-LD, который
  кодируется с `JSON_HEX_TAG` и не может закрыть тег `script`.
- **SEO.** На каждой странице свои title, description, canonical, Open Graph и Twitter Card, хлебные крошки
  и JSON-LD (`WebSite`, `CollectionPage`, `BlogPosting`, `BreadcrumbList`). `sitemap.xml` с датами, `robots.txt`,
  RSS и `llms.txt` для ИИ-агентов собираются из базы. XML пишет `XMLWriter`, текст - PHP: Smarty только для HTML.
- **Статья без обложки.** Обложка необязательна: в карточке её заменяет заглушка основной категории того же размера,
  на странице статьи блока обложки нет, в соцсетях и JSON-LD - картинка сайта.
- **Кэш и версии статики.** Модификатор Smarty `asset` дописывает к адресу `?v=` со временем изменения файла,
  поэтому nginx отдаёт `/assets/` с кэшем на год; обложки и иконки - на 30 дней, всё текстовое - с gzip.
  Шрифт свой (два woff2, ~40 КБ) с preload, у картинок размеры и `loading="lazy"`, первая на экране - `fetchpriority="high"`.
- **Сборка SCSS.** dart-sass одним бинарником, без Node.js, архив проверяется по sha256. В разработке сервис `sass`
  пересобирает CSS при каждом изменении, CI и образ демо собирают его той же версией. Собранный CSS в git не попадает.
- **Вёрстка.** Mobile-first, BEM, без CSS-фреймворков и без JS: меню на телефоне открывается флажком. Широкий контейнер
  до 1440 px - моё решение: мне так нравится, и я считаю это правильным.

## Тесты

247 тестов, PHPStan на уровне max без baseline.

- **Unit** (126) - роутер, запрос, пагинация, разбор `sort`/`page`, генератор статей, slug, `Urls`, `ArticleText`, мета-теги и JSON-LD,
  sitemap, RSS, llms.txt, шаблоны: экранирование, layout, иконки, заглушки, web manifest.
- **Интеграционные** (70) - на настоящем MySQL в базе `blog_test`: подключение и `Row`, схема (уникальность и формат slug,
  одна основная категория, каскадное удаление), все запросы репозиториев, сидер и проверка демо-данных.
- **Функциональные** (51) - приложение целиком через `App::handle()` без HTTP: коды 200, 301, 404, 405 и 500,
  мета-теги, страницы без статей и без обложек, экранирование текста, просмотры только на GET, sitemap, RSS, llms.txt.

Тесты с базой пересоздают схему раз за запуск и очищают таблицы перед каждым тестом, тесты репозиториев и страниц
идут в транзакции с откатом. Части страниц тесты ищут по смыслу разметки (`aria-label`, заголовки), а не по CSS-классам,
поэтому правки вёрстки их не ломают.

CI (`.github/workflows/ci.yml`) на каждый push в `main` и pull request: `composer validate`, PHPStan и PHPUnit на PHP 8.1
и 8.5 с MySQL 8.4, сборка SCSS, сборка образа демо и проверка, что он отвечает.
