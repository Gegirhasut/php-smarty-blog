# Как использовался ИИ

## Что решал я

- Стек и подходы: чистый PHP со своим роутером, Smarty, MySQL 8.4, Docker, SCSS через dart-sass без Node.js,
  PHP 8.5 в окружении при совместимости кода с 8.1.
- Требования к архитектуре: тонкие контроллеры, SQL только в репозиториях, сущности вместо массивов, ленивое
  подключение к базе, без глобального состояния; простота важнее «энтерпрайзности».
- Широкоформатная вёрстка - моё личное решение: мне так нравится, и я считаю это правильным.
- Две колонки на странице статьи вместо узкой колонки с макета; заглушки для статей без обложки.
- Без поиска: в ТЗ его нет.
- SEO и скорость: мета-теги и JSON-LD, sitemap, адреса без дублей, кэш статики; RSS и llms.txt - для читалок
  и ИИ-агентов.
- План по этапам ([plan.md](plan.md)) и приёмка каждого этапа: смотрел сайт на десктопе и телефоне, читал код
  и замечания ревью, решал, что исправлять, и только потом давал push.

## Как применялся ИИ

- **Claude Code** - агенты-разработчики писали код по этапам плана и правилам из `CLAUDE.md`. После этапа - независимый
  агент-ревьюер, который видит только код и ТЗ, и круги «ревью → правки → ревью» до чистого результата.
- **ChatGPT** - макеты страниц (`docs/design`), логотип, иконки сайта, картинка для соцсетей, баннер главной, обложки
  статей и заглушки категорий; в вёрстке они только подключены.
- Тексты демо-статей сгенерированы ИИ.

## Что находило ревью

- **500 на кириллическом адресе.** MySQL не сравнивает колонку slug в `ascii_bin` со строкой с кириллицей, и `/post/статья`
  отвечал 500 вместо 404. Теперь формат slug проверяется до запроса, а сидер такие slug не пускает.
- **Терялась основная категория.** Категории статьи читались в порядке меню, и в крошки попадала не первая из файла
  статьи. Появилась колонка `position`, основная - с наименьшей позицией.
- **Дубли страниц.** `?sort=date` и `?page=1` отдавали ту же страницу с кодом 200 - теперь 301 на адрес без них,
  мусорные параметры - 404.
- **Горизонтальная прокрутка главной на узких телефонах** - исправлено в вёрстке.

## Тесты

PHPUnit: unit, интеграционные на настоящем MySQL и функциональные через приложение целиком (подробнее -
в [architecture.md](architecture.md#тесты)); PHPStan на уровне max без baseline. Новый код приходил вместе с тестами,
ревьюер проверял и их. CI гоняет анализ и тесты на PHP 8.1 и 8.5 с MySQL 8.4 и собирает SCSS.
